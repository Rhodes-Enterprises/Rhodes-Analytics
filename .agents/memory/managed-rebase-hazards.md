---
name: Managed task-rebase hazards
description: Conflict-free auto-rebases can still break the tree; what to re-verify before re-completing
---

- A managed rebase that reports **no conflicts** can still be semantically broken: adjacent-line auto-merges may drop an import the other side added, or land an inserted block far from its intended position (e.g. after the script's top-level entry call, where a `let` is still uninitialized when first used under tsx's relaxed TDZ).
- Another signature: a merge can **glue a declaration onto the end of a comment line** (lost newline), e.g. `// ...comment.const API_BASE =` — the declaration silently becomes comment text and the next line a bare expression, so the identifier is undefined at runtime. tsc never sees files outside tsconfig (audit scripts!), so grep merge-touched script files for `//.*\b(const|let|var|function) \w+ =` when a script suddenly crashes on an undefined top-level identifier.
- Long-running workflows keep serving **pre-rebase code**; an audit or client built from the rebased tree then fails on missing response fields that look like real regressions.
- **How to apply:** after every rebase (managed or manual), before re-running validation or `markTaskComplete`: (1) re-run the root typecheck, (2) `git diff` the merge-touched files against the main ref when anything smells off, (3) restart affected workflows so processes match the tree.
- Rebases do NOT run pnpm install: if the incoming main changed pnpm-lock.yaml (new deps like playwright-core), run `pnpm install --frozen-lockfile` after the rebase or newly-required packages are missing at runtime.
- Observed corruption shapes (all shipped to main unnoticed in files no typecheck covered): a swallowed newline gluing `const X =` onto the tail of a comment line (declaration commented out, initializer left as a floating expression); a whole function body reverted to the branch's stale copy while the other side's call sites kept the newer API (Map vs lookup-function); a helper's definition deleted while a re-added caller survived. Symbol-level typecheck over EVERY merged file (src and scripts) is the only cheap net that catches all three. A fourth shape — the script's trailing `main().catch(...)` invocation dropped while later hunks appended after it — typechecks clean (an uninvoked function is legal TS) and turns the audit into an instant silent PASS; the tell is a sub-second duration with zero output in the audit:all summary. The mirror shape when parallel branches BOTH restore a dropped call: the entrypoint lands twice (audit runs twice, doubled output) — `grep -c "main().catch"` after every rebase; expect exactly 1.
- The BASE your task env is cut from can itself be merge-corrupted (another task's completion rebase landed mangled hunks on main — e.g. one handler body smeared across several route registrations, routes deleted, duplicate registrations). If endpoints 404/502 or root typecheck fails at task START with zero local changes: `git show HEAD -- <file>` / diff HEAD vs HEAD^ on the last-touched files, and reconstruct from the parent commit + the intent pattern visible in surviving hunks. Repair on your branch and report as drift; don't assume your env is at fault.
